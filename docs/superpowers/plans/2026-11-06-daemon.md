# pushwork daemon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run pushwork's commands in a background daemon that holds one Subduction node on the machine store with one connection per sync server, checked and restarted by the CLI on every command.

**Architecture:** A length-prefixed CBOR RPC over a unix socket (named pipe on Windows) carries calls to `src/pushwork.ts` functions, with function arguments marshalled as callable handles. The daemon owns a `Hub` (one node, the machine `FsStorage`, the allowlist, a connection per server); `Docs` uses it when given `hub`, for every plain repo, online or offline. The CLI says hello with its version, starts or restarts the daemon as needed, and falls back to running in-process if it can't start one.

**Tech Stack:** TypeScript (Node ≥ 24, CommonJS output), `@automerge/automerge-subduction` 0.16.1, `cbor-x` (already a dependency), `node:net`, vitest.

**Spec:** `docs/superpowers/specs/2026-11-06-daemon-design.html`. Builds on the machine store (`docs/superpowers/specs/2026-11-05-machine-store-design.html`), which is done on this branch.

## Global Constraints

- No new dependencies.
- Socket: `path.join(os.homedir(), ".pushwork", "daemon.sock")`; if that is longer than 100 bytes, `/tmp/pushwork-<uid>/<first 12 hex of sha256(home)>.sock` with the directory created mode `0o700`. Windows: `\\.\pipe\pushwork-<first 12 hex of sha256(home)>`.
- Pid file `~/.pushwork/daemon.pid`; log `~/.pushwork/daemon.log` (truncated when a daemon starts).
- Daemon version string: `` `${versions.pushwork}+${mtimeMs of dist/daemon.js}` `` (the compiled daemon module's own file).
- Timeouts: hello 2000 ms; daemon start 10000 ms; idle exit 10 minutes with no call in flight; home check every 30000 ms (exit when `~/.pushwork` no longer exists).
- Keyhive repos never use the hub (their `Docs` get their own node, as now). `yoink`, `yeet`, `shape install`, `keyhive check`, `Docs.pull()`, `fetchCard` keep their `MemoryStorage` nodes.
- Error text (exact): mid-command death → `the pushwork daemon stopped while running this command`; fallback warning → `couldn't start the pushwork daemon (see ~/.pushwork/daemon.log); running here instead`.
- Commits: plain imperative messages, **no `Co-Authored-By` trailer**. Tabs, existing comment voice. Checks: `pnpm test`, `pnpm typecheck` (`pnpm lint` can't run: ESLint isn't installed).

## Review Focus

1. **The daemon's view of the store going stale.** Every store write in the daemon must go through the hub's node; anything that writes the store directly (migrate's import) must be followed by a hub reset. Test in Task 2 (shared-node scenario) and Task 3 (migrate through the daemon, then sync).
2. **A stale daemon after an upgrade.** A rebuilt `dist/daemon.js` must restart the daemon on the next command. Test in Task 3.
3. **Output and exit codes unchanged.** Errors thrown in the daemon must surface with the same message and exit code 1; the whole existing integration suite runs through the daemon. Task 3.
4. **Daemons left behind by tests or deleted homes.** A daemon whose home is deleted exits within ~30 s; the suite's shared home's daemon is stopped in global teardown. Task 3.
5. **Two commands at once.** Concurrent commands in different checkouts share the node; a second command in the same checkout fails on the checkout lock as before; `migrate` waits for in-flight calls and blocks new ones while it resets the hub. Test in Task 3.

### Task 1: RPC over a socket

**Files:**
- Create: `src/rpc.ts`
- Test: `test/unit/rpc.test.ts`

**Interfaces:**
- Produces:
  - `type Handler = (method: string, args: unknown[]) => Promise<unknown>`
  - `class RpcPeer { constructor(socket: net.Socket, handle?: Handler); call(method: string, args: unknown[]): Promise<unknown>; onClose(cb: () => void): void; close(): void }`
  - Framing: 4-byte big-endian length, then `cbor-x` `encode` of a message. Messages: `{ t: "call", id, method, args }`, `{ t: "result", id, value }`, `{ t: "error", id, message, name }`, `{ t: "invoke", id, fn, args }` (call a marshalled function), answered with result/error like a call.
  - Functions anywhere in `args`, `value` or invoke args (top level, arrays, plain objects, recursively) are replaced by `{ $fn: <number> }` and turned back into async stubs on the other side. Stubs stay valid until the peer closes.
  - Pending calls reject with `Error("connection closed")` when the socket closes.

- [ ] **Step 1: Write the failing tests** (pair two `RpcPeer`s over `net.createServer` on a temp socket path, or a `net.Socket` pair):
  - `"round-trips bytes, maps and nested objects"`: handler echoes; `new Uint8Array([1,2,3])`, `new Map([["a",1]])`, `{ x: [1, { y: "z" }] }` come back equal.
  - `"calls back a function argument"`: handler calls `args[0]("hi")` and returns its result; caller passes `async s => s + "!"`, gets `"hi!"`.
  - `"calls a function inside an object passed to a callback"`: handler calls `args[0]({ viewCode: () => "code" })`; the caller's callback calls `viewCode()` and returns it; result `"code"`.
  - `"rethrows errors with their message"`: handler throws `new Error("nope")`; `call` rejects with message `"nope"`.
  - `"rejects pending calls when the socket closes"`: handler never resolves; destroy the server socket; `call` rejects with `"connection closed"`.
- [ ] **Step 2: Run:** `pnpm vitest run test/unit/rpc.test.ts` → FAIL (module missing).
- [ ] **Step 3: Implement `src/rpc.ts`.** Buffer partial frames; a frame may arrive split or several at once.
- [ ] **Step 4: Run:** same command → PASS.
- [ ] **Step 5: Commit:** `git commit -m "Add an RPC for calling pushwork over a socket"`

### Task 2: The hub — one node, a connection per server

**Files:**
- Create: `src/hub.ts`
- Modify: `src/docs.ts` (export `connect` and `Connection`; `DocsOptions.hub`; `open`, `connect`, `close`)
- Modify: `src/pushwork.ts` (`openDocs` uses `currentHub()` for non-keyhive repos)
- Modify: `test/server.ts` (`startServer` also returns `connections(): number`, counting accepted websocket connections)
- Test: `test/unit/hub.test.ts`

**Interfaces:**
- Produces:
  - `class Hub` in `src/hub.ts`:
    - `static open(storage: FsStorage, signer: Signer): Hub` (node built with the hub's `Allowlist` policy and ephemeral policy, as `Docs.open` does)
    - `readonly node: Subduction; readonly storage: FsStorage; readonly allowlist: Allowlist`
    - `connect(server: string): Promise<Connection>`: returns the cached peer if `node.getConnectedPeerIds()` still includes it (with `connectMs: 0`), else dials with `connect()` from `src/docs.ts` and caches a successful peer; concurrent calls for one server share one dial.
    - `servers(): Promise<{ server: string; peer: string }[]>`: connected servers (peer as hex).
    - `close(): Promise<void>`: `disconnectAll`, `free`.
  - `setHub(hub: Hub | undefined): void`, `currentHub(): Hub | undefined` (module-level).
  - `DocsOptions.hub?: Hub`: `Docs.open` uses `hub.node` and `hub.allowlist`, and `hub.connect(server)` for its connection; `options.storage` must be `hub.storage` (throw otherwise). `Docs.connect(server)` goes through the hub. `close()` saves and compacts but leaves the node and its connections alone.
  - `openDocs` in `src/pushwork.ts`: when `currentHub()` is set and there's no `hive`, pass `hub` and `storage: hub.storage`; otherwise unchanged.

- [ ] **Step 1: Write the failing tests** in `test/unit/hub.test.ts` (temp `FsStorage`, `MemorySigner.generate()`, `startServer()`):
  - `"two Docs on one hub open one connection"`: open, create, sync, close twice through the hub → `server.connections()` is 1.
  - `"re-dials a server that dropped the connection"`: after one sync, `server.node.disconnectAll()`; wait until the hub's node no longer lists the peer (poll ≤ 2 s); next `Docs` sync succeeds and `connections()` is 2.
  - `"closing Docs leaves the connection open"`: after `close()`, `hub.servers()` still lists the server.
  - `"writes from one command are sent by the next"` (the spike): 12 commands through one hub alternating offline (`server` unset, `save`) and online (`sync`), 8 changes each; a fresh `MemoryStorage` `Docs` reading from the server sees the same counter value as local.
  - `"refuses a storage other than the hub's"`: `Docs.open({ hub, storage: new MemoryStorage(), … })` rejects.
- [ ] **Step 2: Run:** `pnpm vitest run test/unit/hub.test.ts` → FAIL.
- [ ] **Step 3: Implement** `src/hub.ts`, the `Docs` changes, the `openDocs` change and the server counter.

### Task 3: The daemon and the CLI talking to it

**Files:**
- Create: `src/daemon.ts` (server side, `socketPath`, `daemonVersion`)
- Create: `src/client.ts` (start/check/restart, `remote()`, `stopDaemon()`, `daemonStatus()`)
- Modify: `src/cli.ts` (`--no-daemon`; every call into `./pushwork.js` goes through `api`; `daemon` command with `status`, `stop`, and hidden `run`)
- Modify: `test/global-setup.ts` (teardown runs `node dist/cli.js daemon stop` with the test home)
- Test: `test/integration/daemon.test.ts`

**Interfaces:**
- Consumes: `RpcPeer` (Task 1); `Hub`, `setHub`, `currentHub` (Task 2); `storeDir()` (`src/config.ts`), `loadSeed`/`signerFrom` (`src/key.ts`), `versions` (`src/version.ts`).
- Produces:
  - `src/daemon.ts`: `socketPath(home = os.homedir()): string`; `daemonVersion(): string`; `runDaemon(): Promise<void>` (listen, write pid file, `setHub(Hub.open(await FsStorage.open(storeDir()), signerFrom(await loadSeed())))`, serve until stopped/idle/home gone; unlink the socket and pid file on exit).
  - Daemon methods: `hello() → { version, pid }`; `status() → { pid, version, startedAt, servers }`; `stop() → true` then exit; `call(fn: string, args: unknown[]) → result` where `fn` is one of the names `src/cli.ts` imports from `./pushwork.js` (a fixed list; anything else throws `unknown command ${fn}`).
  - `call("migrate", …)` waits for in-flight calls, holds new calls until done, then replaces the hub (`hub.close()`, new `Hub.open`, `setHub`).
  - `src/client.ts`: `type Api = Pick<typeof import("./pushwork.js"), Names>`; `remote(): Promise<Api>` (hello within 2000 ms; on a version mismatch send `stop` and wait for the socket to go; on no answer kill the pid from the pid file; start `process.execPath dist/cli.js daemon run` detached with stdio to the log; retry for 10000 ms; throws if it never answers); `stopDaemon(): Promise<boolean>` (true if one was running); `daemonStatus(): Promise<… | undefined>`.
  - A call whose socket closes before answering rejects with `Error("the pushwork daemon stopped while running this command")`.
  - `src/cli.ts`: `api` is the `./pushwork.js` module itself with `--no-daemon` (after `await stopDaemon()`), else `await remote()`; if `remote()` throws, warn the exact fallback text and use the module itself.

- [ ] **Step 1: Write the failing tests** in `test/integration/daemon.test.ts`, each in its own temp home via `homeEnv(home)` from `test/home.ts`, with a counting `startServer()` and `afterEach` running `daemon stop` for that home:
  - `"two syncs share one connection"`: `init --sync-server <url>`, edit, `sync`, edit, `sync` → `server.connections()` is 1.
  - `"daemon status reports a running daemon"`: after one command, `daemon status` output includes the pid from `~/.pushwork/daemon.pid`.
  - `"a killed daemon is replaced on the next command"`: `process.kill(pid, "SIGKILL")`; `status` in the repo succeeds; the pid file holds a new pid.
  - `"a newer daemon build restarts it"`: set `dist/daemon.js`'s mtime forward with `fs.utimes` (restore it in `finally`); next command succeeds with a new pid.
  - `"--no-daemon stops a running daemon and works without one"`: `--no-daemon status` succeeds; `daemon status` afterwards says it isn't running.
  - `"errors come back with their message and exit 1"`: `status` outside a repo rejects with `/not a pushwork repo/`.
  - `"exits when its home is deleted"`: start one, `rm -rf` the home, the pid is gone within 40 s.
  - `"a sync after migrate through the daemon publishes the imported commits"`: build a v6 fixture as `test/integration/migrate.test.ts` does (offline init in another home, one saved-but-unsynced edit), `migrate --sync-server <url>` through the daemon, `sync`, then a fresh clone elsewhere has the edit.
  - `"two commands in different checkouts run at once"`: two repos, `Promise.all` of two syncs succeeds.
